# Changelog

ecash-wallet 0.1.2 builds on `sp-wire` 0.2.0 (wire version 2) and the 0.1.2 mints. 0.1.1 moved the types to `sp-wire`, added the wire-version check and removed the mint crates from the library. 0.1.0 is the first release. Nothing was recorded per version before this file; the section below is everything the README said about what was built and when.

## Unreleased

- AIR 2.1.0 (commit `741b1cf`) comes with the next sp-wire (0.4.1): `PublicKey` and `SecretKey` are the same types under the same names, the sealed bytes and the `mint_did_key.json` format are unchanged, and `WIRE_VERSION` stays 2. the wallet's code is not changed for it. The wallet's `sp_wire::seal` uses are unchanged.

## 0.5.0 (2026-10-17)

- The fee the wallet assumes before it has read `GET /fees` is 0, the mint's new default (esp-mint 0.5.0); it was 1,000,000. The rate in force is still read from the mint before a redemption is built. REGTEST.md starts esp-mint with `ESP_REDEEM_FEE_PER_BYTE=1000000` so that its redemption steps still show a fee.
- Lint cleanups, no change in behaviour (`single_match` in `reclaim_handoff`, `needless_bool` in the redeem rollback, an assertion on a constant in a test).
- `--help` lists `migrate` and `--mainnet`, which the code already had. README: `fsp issue`, `fsp pay` and `fsp sync` show `--service` as optional (the storage service is the default, as the code does), `esp-schedule` takes no `--service`, the synopsis shows `--config`, and the mints' tags are `psp-mint` v0.3.0, `esp-mint` v0.5.0 and `fsp-mint` v0.4.0.
- **The handoff is split into two kinds. This changes the string format and the command line** (`src/handoff.rs`, `src/main.rs`). The 0.4.0 combined handoff let you build combinations that are not valid, which was a bug. Now: a **PSP handoff** (`SPHP1:`; a developer to a user): PSP notes only, never a DID key or FSP, always sealed to the recipient's DID public key with `sp_wire::seal` (AIR's own encryption; no new crypto), always swapped at the PSP mint on import with no way to opt out, and if the mint cannot be reached the notes stay unswapped (they count in the balance and can be spent: see "No lock on unswapped received PSP" below) and the swap is sent again on the next sync. An **FSP handoff** (`SPHF1:`; moving the user's own DID to a new device): always the DID secret key plus a little FSP, never swapped, not encrypted (it carries the key it would be encrypted to); the bearer and key-exposure warning is printed on export and on import. Each kind has its own types (`PspPayload` has no field for a key or FSP, `FspPayload` has a non-optional key), its own prefix and its own import; the old `SPH1:` is refused with a message. API: `export_psp_handoff`, `export_fsp_handoff`, `import_psp_handoff`, `import_fsp_handoff`, `import_handoff` (either kind), `select_psp_handoff`, `select_fsp_handoff`, `kind_of`, `HandoffKind`. Removed: `export_handoff`, `select_handoff`, `HandoffSelection`, `Payload`, `build_fsp_swap_of`, the `--swap` option, `PREFIX` and `BEARER_WARNING` (now `PSP_PREFIX`, `FSP_PREFIX`, `PSP_WARNING`, `FSP_WARNING`). Command line: `handoff export-psp --to DID --psp N`, `handoff export-fsp --fsp SERVICE:UNITS --did-key-file FILE`, `handoff import STRING [--did-key-file FILE] [--did-key-out FILE]`; `handoff export` explains the split. `Balance::unswapped_psp` and a `balance` line show PSP waiting for its swap. Old records in `handoffs_out` and `handoffs_in` read as kind `combined`. A PSP handoff is about 188 + 150 per note in characters (27 fit a QR code at level L, 21 at M), an FSP handoff about 165 + 150. The `merge FILE` after an FSP handoff and the AIR fetch is documented as a separate step; the fetch does not exist yet.
- **`send-psp` is removed; the PSP handoff gets its reclaim** (`src/handoff.rs`, `src/http.rs`, `src/legacy.rs`, `src/main.rs`; replaces the earlier decision to keep `send-psp`). Removed: the commands `send-psp`, `receive-psp` and `sent` (they print what replaces them), the `psp1` token (`Token`, `TokenNote`, `TOKEN_PREFIX`), `export_psp`, `export_psp_amount`, `begin_receive`, `settle_sent`, `sent_tokens`, `http::receive_psp`, `http::check_sent`, `http::reclaim_sent`, `Received`, and the module `send` (the swap builder moved into `handoff.rs`). Added: **`handoff check ID`** and **`handoff reclaim ID`** (`http::check_handoff`, `http::reclaim_handoff`, `Wallet::settle_handoff`, `Wallet::begin_reclaim`, `Wallet::handoff_standing`, `handoff::Standing`, `http::Reclaim`): the logic of `sent --check` and `sent --reclaim`, with the mint's `/check-state` record deciding who wins (none spent: still the sender's; all: the receiver has it and the handoff is done; some: those are dropped and the rest reclaimable) and a reclaim being a stored swap back to the sender that the mint takes or refuses against the receiver's. `OutgoingHandoff` gains `mint`, `reclaim` and `spent_elsewhere` (all with defaults, so old files read), and `HandoffState` gains `Reclaimed`. A reclaim's outcome and the handoff's state change in the same write. `cancel` is refused while a reclaim is stored.
- **Old `send-psp` records are migrated, not kept** (`src/legacy.rs`, `WalletData::migrate_legacy`). A wallet file's `sent` list is read as before and each token becomes a PSP handoff record with the token's id when the file is opened and when two copies are merged (pending, a stored reclaim, received, conflict, reclaimed; the table is in `legacy.rs`). They are checked and reclaimed with `handoff check` and `handoff reclaim`, including a reclaim that was stored and not sent. The file is rewritten without `sent` at the next save. A swap that `receive-psp` stored and did not send (`receive|<id>`) is still sent at the next start; `Wallet::legacy_receive_psp` and a `balance` line show it, and it is not counted in the balance (the wallet holds no secrets for those notes). A `psp1` token string can no longer be imported.
- **No lock on unswapped received PSP.** A PSP handoff's notes are added to the wallet on import and **count in the balance**, with a stored swap beside them. The swap is sent first whenever the mint can be reached: on import, then on every sync (`rotation_sync` sends stored swaps first) and at every start. Spending a note at the mint burns it just as the swap does, so the lock added nothing once `send-psp` was gone. A stored swap is made to fit what the wallet still holds before it is sent (`Wallet::live_swap`), the ordinary rollover leaves those notes alone, and a note the mint says is spent (the sender reclaimed first, or a copy was received first) is moved to the spent record, so it leaves the balance, and the rest is swapped (`Wallet::swap_found_spent`). Any other refusal drops the stored swap and leaves the notes in the balance. `Balance::unswapped_psp` is now a part of `Balance::psp` (it was in no total), and the `balance` and `handoff list` lines say so. **Behaviour change:** a received PSP handoff can be spent before it is swapped; until the swap goes through the sender can still reclaim it.
- Tests: `tests/handoff_flow.rs` replaces `tests/send_flow.rs` (removed): reclaim before the receiver swaps (fresh notes for the sender, a late receiver loses them from the balance), reclaim after the receiver swapped (nothing comes back, done), a note spent elsewhere (check says partly, the rest is reclaimed; a receiver drops the spent one and swaps the rest), unswapped notes counted and spendable and swapped at the next sync, a spent note left out of the swap, and old `send-psp` records loading (pending, received, reclaimed, and a stored reclaim finished by `handoff check`). Unit tests in `handoff.rs` and `legacy.rs` cover the states, the stored reclaim, the stored-swap rebuild and the migration. The token test in `tests/keyset_refusals.rs` is removed with the token.
- Tests: unit tests for every wrong combination and the format, and `tests/handoff_flow.rs` for the PSP swap at a real psp-mint with the right and the wrong key, the unreachable-mint retry, and the FSP round trip at a real fsp-mint.

## 0.4.0 (2026-10-17)

- **Handoff.** `export_handoff` and `import_handoff` (`src/handoff.rs`) move PSP notes, FSP notes (with their service) and optionally a DID secret key from one wallet to another as one string, with no AIR: `SPH1:` and then base 44 (the QR alphanumeric characters), versioned and checked, at most 1000 notes, about 60 + 150 per note in characters and 48 more with a DID key (28 notes fit a QR code at level L, 22 at M). It holds bearer secrets, and says so in the docs and in every command output. Exported notes leave the balance in the same write (`pending`); `cancel_handoff` puts them back, `finish_handoff` drops them. Import validates against the wallet's key sets, mint and service, refuses a damaged, wrong-version, forged or already imported payload, adds the notes and records their source (`handoffs_in`). `--swap` swaps them at their mint (PSP like a received token, FSP by a normal swap) in `http::complete_import`. Command line: `handoff export|import|list|cancel|done`. No QR crate was added; pipe the string to `qrencode`.
- **Merge.** `merge`, `Wallet::merge_from` and `Wallet::merge_file` (`src/merge.rs`) reconcile a wallet retrieved from storage with the local one: notes united by identity, a note spent, lost or handed off in either copy stays gone, pending requests united without duplicates, the same result in either direction. The wallet file gains a `version` counter (up by one per write), departure and return counters per note and a set of finished request ids (about 70 bytes per spent note); old files read as zeros. Command line: `merge FILE`.
- **Service ID on FSP notes.** `StoredNote::fsp_service()`; `balance` groups FSP by service (`Balance::fsp_by_service`) and `balance` prints it per service; the handoff carries the service. `fill_fsp_services` migrates old wallet files at startup from the stored FSP mints; a note that cannot be placed stays `unknown` and is not guessed. No wire change (the service is not part of what fsp-mint signs); fsp-mint already reports its service in `/keys` and `/health`.
- **Storage policy settings.** New `src/config.rs` and `config.toml` (beside the wallet file, `--config FILE` or `$ECASH_CONFIG`) with `storage.wallet` and `storage.app` (`$ECASH_STORAGE_WALLET`, `$ECASH_STORAGE_APP`): an ordered list of service IDs, index 0 the primary, parsed and checked by `sp_wire::storage` (shared with the mints). One entry is valid, empty means local only. **The wallet's storage service for FSP fees is the primary of `storage.wallet`** (`Settings::storage_service`), not whichever service its notes are for: the `fsp issue|pay|sync` commands default `--service` to it, and `balance` shows the FSP held for it. New command `config`. Config and validation only; nothing reads or writes the AIR. New dependency `toml` 0.8; `sp-wire` is now the `v0.4.0` tag. Tests: the defaults, file then environment with sources, a named file, every mistake listed, an empty list.
- `handoff::swap_keyset` and `fsp::build_swap` are `pub(crate)` (used by the handoff). New tests: `handoff.rs` and `merge.rs` unit tests and `tests/handoff_flow.rs`. The new test file needs the local mints like `fsp_flow` (see the README).

## 0.3.0 (2026-10-16)

- **ESP notes are powers of two.** The ESP mint now refuses any ESP amount that is not a power of two (`bad_denomination`), so the wallet only builds those. New `src/split.rs`: `split` (a total into the fewest powers of two, largest first), `split_into` (the same total in exactly n notes, by halving the largest) and `check_denomination`. `build_exchange` splits the amount and the change; `build_transfer` splits the total; an explicit `--amounts` list is refused if any size is not a power of two, and a chosen input note that is not one is refused. A redemption's decline and refund outputs are split the same way: the count of outputs and the fee depend on each other, so `allocate` tries counts upward for the smallest that fits (see the ESP DESIGN.md). `redeem::MAX_OUTPUTS_PER_TERMS` (64, one per size) is public and is the worst case the group-size estimate uses.
- Tests: `split` and `split_into` (round-trip, largest first, above 2^63, the limit); an amount that is not a power of two is refused in the exchange and the transfer; a total above one note splits over several notes, and so does the change; the redemption fee and count tests and the end-to-end flows moved to power-of-two sizes. **Needs esp-mint with the same change:** the integration tests use the mints at their git tags, so they see the new check only after the tag moves.
- Tests can be run against the local mint folders with `sandbox-mint/scripts/test-wallet-against-local-mints.sh` (see the README), for a release where the wallet and a mint change together. The script runs every test file to the end (`--no-fail-fast`) and also runs fsp-mint's tests.
- Tests: the wallet's three mint-hosting tests (`redeem_flow`, `fsp_flow`, `rotation_flow`) set esp-mint's new `in_flight` field, so they build against esp-mint after the lock change, not the `v0.2.0` tag. `rotation_flow` uses ESP notes of 4, 4 and 2 (powers of two); `flow` counts every note it holds.
- Docs: why there is no ESP split command (holders convert ESP to FSP straight away), and why a lost wallet file is not rebuilt (the AIR keeps the storage redundant).
- **A swap time is never the second the set starts.** The random delay is now 1 to the window (0.5% of the period, at most 72 h), not 0 to the window. With 0 possible, a wallet that synced the second a set started swapped at once, for about 1 wallet in 19 on a 1-hour period (1 in 4,321 on the 240-hour test period). It showed as a rare failure in `rotation_flow`: the rotation tests set the mint's clock to the start and expect "will be rolled over" before the swap, and the first sync had already done it. A unit test checks 20,000 draws.

## 0.2.0

- **No re-blinding.** `reblind_exchange`, `reblind_transfer`, `reblind_redemption` and `error::is_keyset_not_current` are removed, with their tests and the retry in the command line (`exchange`, `transfer`, `redeem`), in rollovers and in the PSP receive swap. Mints now sign with whichever live keyset a request names, so a pending request keeps the keyset its outputs name and is sent as it is. A request whose keyset has been deleted is refused `keyset_retired` before anything is burned, the notes are freed, and the request is built again. The staggered rollover is unchanged.
- Against a mint of an earlier release (which still answers `keyset_not_current` for the previous set) a stale request is a plain refusal with nothing burned; build it again.
- Test: a transfer built from the stale cache after the ESP mint rotated is signed by the set it names, and the new notes record that set.
- **The wallet links no mint crate.** `mint-server` is now a dev-dependency only; `http` is just `reqwest`. `GET /keys` and `POST /check-state` use `KeysResponse`, `CheckStateRequest` and `CheckStateResponse` from the new `sp_wire::keys` module (same JSON as mint-server's types).
- **A PSP purchase names a key set.** `build_psp_payload` puts the PSP's key set the wallet last saw in the payload (the single live one it knows; none if it knows none or two), and the mint signs with it while it is live. `buy-psp` has a `--psp-url` flag that reads the PSP's live sets first. Test: `a_purchase_names_the_psp_keyset_the_wallet_last_saw`.
- **No fixed cap of 2^24 on a PSP note.** `psp::MAX_PSP_DENOMINATION` is removed. `buy-psp --psp-url` reads the PSP's largest note from `GET /keys` (`http::sync_psp_limits`, `Wallet::psp_max_denomination`) and refuses a larger one; offline only the power of two is checked. Test: `the_largest_note_is_the_one_the_psp_says`.

### Rotation of PSP and ESP

*What changed in the old rule:* "a note with no recorded set counts as previous" now applies only to notes from before keysets were recorded, and a wrong guess burns nothing (the mint refuses a note that does not verify under the keyset named).
