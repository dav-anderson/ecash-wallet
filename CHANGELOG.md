# Changelog

ecash-wallet 0.1.2 builds on `sp-wire` 0.2.0 (wire version 2) and the 0.1.2 mints. 0.1.1 moved the types to `sp-wire`, added the wire-version check and removed the mint crates from the library. 0.1.0 is the first release. Nothing was recorded per version before this file; the section below is everything the README said about what was built and when.

## 0.6.0, the stand-alone hand-over and transfer commands are gone (unreleased)

They were for passing ESP between two terminals before AIR; `fsp issue` now carries the ESP hand-over to the FSP mint over AIR.

- **Changed: the fallback window for an open purchase or reply key is 14 days, not 7** (`OPEN_KEY_FALLBACK_SECS`), to match the PSP's default reconciliation window. It applies only when a record names no window (or a wallet file from before windows has none); a record that names one is used as before.
- **Removed: the `hand-over` and `transfer` commands** (`hand-over --service DID (--esp UNITS | --psp N) [--day D] --out FILE`, and `transfer --service-key HEX [--day D] [--amounts A,B,C] [--resume ID]`), and in the library `Wallet::hand_over_esp`, `Wallet::cancel_transfer` and `Wallet::mark_spent_in_transfer`. A wallet file written by an older version may hold a pending transfer; nothing cancels one now, and its notes stay reserved (`balance` still lists it).
- **Kept: `receive FILE`**, now described as taking in the output of fsp-mint's `export-esp` and nothing else, with `Wallet::receive_handover` and the `Handover` file format (and `store::Handover` and `HandedNote`, which `fsp issue` also uses for its record of what it handed over). Also kept: `pick_exact`, which `fsp issue` uses to choose the ESP notes of a hand-over.
- **Changed: `build_transfer` and `finish_transfer` are `#[doc(hidden)]`.** Only `esp_air_flow` and `rotation_flow` call them (with `mint_info::send_transfer`), to play the service against esp-mint, and no command does. They could not move into `tests/`, because they write through `Wallet::update`, which is private to the crate.
- **Removed: `tests/transfer_flow.rs`** and the unit tests in `transfer.rs` of what was removed (an exact hand-over, an amount no set makes, one service, one day, reserved notes, a spent note named in a transfer, a cancelled transfer). The two `receive_handover` unit tests now build their handover directly. The transfer through esp-mint (the supply unchanged, a resend answered from the stored reply, a double presentation refused) is still covered over AIR by `esp_air_flow` and `rotation_flow`, which need `air-listener-tests`; what is lost is the in-process run in plain `cargo test`, and the exchange-then-hand-over chain.
- Docs: README (the command table, the calls the wallet makes), DESIGN ("The service takes in ESP, and the service's swap", the tests), REGTEST (steps 14 to 20 removed; the service's ESP now comes through FSP issue, `export-esp` and `receive` in step 26, with the FSP mint set up there; steps 27 to 28, 31, 33, 35 to 41 and 45 to 48 rewritten or recomputed and marked not run; step 39 no longer splits a note and step 40 splits a redemption over two notes instead), the help text, and `lib.rs`.

## 0.6.0, PSP signatures delivered over AIR (unreleased)

Builds on `sp-wire` 0.5.0 (`air_request::delivery`) and psp-mint 0.5.0, which writes the records. `Cargo.toml` still names both by their old tags, which move when the new releases are tagged; until then the integration tests run against local copies (`scripts/test-wallet-against-local-mints.sh` in sandbox-mint), and `flow` needs that too, because it reads what psp-mint stores for the payer.

- **Behaviour change: the PSP delivers a purchase's signatures, or that the payment is held, or its rejection, over AIR, and the wallet claims them with no paste.** `claim-psp` with no input reads the delivery record of every pending purchase, waits up to `--wait SECONDS` (60 by default) for the ones not there, checks the PSP's signature, claims the notes and clears the purchase. A held payment or a rejection keeps the purchase and its key open (below) and shows the reason and what was paid; the bitcoin that was paid is not refunded (psp-mint has no refund path). It exits with an error, naming the purchases, if any was not delivered. The same pickup runs once when any command starts, if a purchase is pending (a note instead if `air.server` or `air.host` is missing).
- **Removed: the paste path.** `claim-psp --file`, standard input and `BLIND_NONCE:SIGNATURE` pairs (a command that is given them is refused with a message saying so), and in the library `psp::parse_signatures`, `psp::parse_keyset`, `psp::claim_keys_with`, `Wallet::claim_psp`, `Wallet::ours` and `mint_info::psp_claim_keys`. The record carries the keysets, so claiming makes no keys call.
- **Behaviour change: every PSP purchase has a reply key of its own.** `build_psp_payload(outputs, mint_did_pubkey)` makes a fresh key, puts its public half in the payload as the reply DID and saves the secret (`PendingPurchase::reply_secret`) and the delivery id (`PendingPurchase::delivery_id`) before it returns, so the PSP cannot link two purchases and the key is on disk before any payment. **Removed:** `buy-psp --reply-did` (refused with a message saying why), `Wallet::reply_did()` and `WalletData::reply_did`. The key is never part of a handoff.
- **New: `OpenReply` and `WalletData::open_replies`.** When a record says the purchase may still be open (a credit is owed, or outputs were neither signed nor reported as dropped) the key is kept here after the notes are claimed, because the PSP will write a follow-up record to it. Nothing reads that follow-up yet (its address and shape are not designed). The key is deleted when the PSP's window for the credit closes (`OpenReply::open_until`, from the record; 14 days after it was applied when the record names none). `merge` unites them.
- **New: `psp::apply_delivery` and `mint_info::psp_pickup`.** `apply_delivery(purchase_id, &Outcome) -> Delivered` (`Claimed`, `Open`, `AlreadyDone`) is all or nothing and writes nothing for a purchase that is no longer pending, so reading the same record twice changes nothing. `psp_pickup(wallet, air, wait_secs)` reads every pending purchase's address in one connection, opens each record with the purchase's key, and applies it; a record that fails a check (not the PSP's signature, or not sealed to the purchase's key) is that purchase's `Pickup::Bad` and changes nothing.
- **Old files still read.** A wallet file from before this change reads: its `reply_did` is ignored, and a pending purchase without a key is `Pickup::NoKey` (it cannot be picked up; there is no command to discard it, only the library's `discard_purchase`).
- **Left over:** `store::parse_did` has no caller outside its test, and `http.rs` is still to be removed by `git rm`.
- **New: held and rejected purchases stay open for the PSP's reconciliation window.** The PSP now delivers a record for a payment it holds (`Held`) and for a rejection, with what it received and `open_until`. `apply_delivery` keeps such a purchase and its reply key, marked open (`PendingPurchase::open: Option<OpenPurchase>`, with `OpenKind::{Held, Rejected}`), and returns `Delivered::Open`. `psp_pickup` reports it as `Pickup::Open` and afterwards as `Pickup::StillOpen` without reading the server (`Pickup::Rejected` is gone). `Wallet::close_expired(now)` deletes an open purchase and its key once `open_until` has passed, and an `OpenReply` past its own; every command calls it at startup. `claim-psp` lists open purchases and does not treat them as failures. The wallet has no setting for the window: it is the PSP's (`settle.reconciliation_window_days`, 14 by default). The corrected request or credit that would settle an open purchase is not built.
- **Tests:** new `tests/psp_delivery.rs` (feature `air-listener-tests`): settled, delivered and claimed with no paste; a record read twice (by a copy of the wallet, and by the wallet that already claimed it); a rejection kept open and closed with the PSP's forfeit; a held payment; a credit's key kept until the PSP's window closes; the AIR server down at settlement and a later retry delivering one record; a record that is not the PSP's, or not sealed to the purchase, refused; a wallet file from before purchases had keys; missing AIR settings. `flow` and `rotation_flow` take the outcome psp-mint stored for the payer and apply it. **Deleted, with what covers them:** `signatures_for_outputs_the_wallet_did_not_ask_for_change_nothing` (now `a_record_for_a_purchase_the_wallet_does_not_hold_changes_nothing`); the unit tests of `parse_signatures`, `ours` and `parse_keyset` (the paste format is gone); the three `psp_claim_keys` cases in `air_flow` (keys of no keyset, of a named live keyset, of a retired one; the record carries its keys, and the keyset check is in `psp.rs`'s tests of a bad record), and the end of the rotation test that a retired set's printed signatures are refused (a record claims whenever it is picked up).
- Docs: README (the delivery bullet, the command table, the test section), DESIGN (PSP, the reply DID), REGTEST (steps 3, 5, 8, 9, 23 to 25) and the help texts.

## 0.6.0, HTTP gone from the wallet: every mint over AIR (unreleased)

- **Behaviour change: the PSP, the ESP and the FSP mints are reached over AIR only.** Every wallet call to the PSP (mint info, keys, keysets, rotation window, rollover, check-state), to the ESP (mint info, keysets, rotation window, fees, rollover, exchange, transfer, redeem) and to a service's FSP mint (mint info, keys, rotation, fees, issue, spend) goes over AIR, and the HTTP branch of each is removed. `air.server` and `air.host` (`$ECASH_AIR_SERVER`, `$ECASH_AIR_HOST`) are now required for the PSP's and the ESP's calls, and the service's `air.fsp` entry for an FSP mint's: without them the command stops with an error that names the missing setting, and nothing is sent or written. There is no switch back to HTTP. The built-in SPI and ESP DIDs still apply (both are placeholders until the first SPI deploy), and `air.psp_did` and `air.esp_did` still override them.
- **New: `air.fsp` (`$ECASH_AIR_FSP`), where each service's FSP mint is.** An FSP mint is a service's own, so each service has its own entry, `<service DID>@<AIR server key>@<host>` (the DID the requests are sealed to and the replies signed under, the AIR server the mint's own listener is on, and where it is); comma-separated in the environment, an array of strings or one string in the file; each part checked as `air.server` and `air.host` are, and no service twice. `fsp-mint serve` prints its entry. The `fsp` commands (and the startup FSP sync) for a service with no entry are refused, naming `air.fsp`, and nothing is sent. The entry is marked in the code, the docs and the setting's text as **to be replaced by DID resolution**. `AirSettings::fsp`, `FspAir` (with `parse`), `AirSettings::fsp_for`, and `config::Party::Fsp(service)`.
- **Behaviour change: `--fsp-url` and `$ECASH_FSP_URL` are gone**, from `fsp issue`, `fsp pay`, `fsp sync` and `fsp-window`, with `DEFAULT_FSP_URL`; a flag or variable left in a script is refused or does nothing. The FSP mint record the wallet keeps (`fsp_mints`) is keyed by the service as before and no longer holds a URL: older files still read (the `url` is ignored and not written again). An FSP handoff names its mint by the service hex in the group's `mint` field (the field is part of the string's format and is not empty); the importer ignores it. The swap schedule key for an FSP mint is `<kind>|<service hex>|<keyset>`; an entry an older file keyed by URL is left behind, harmless.
- **Behaviour change: `--psp-url`, `--esp-url`, `$ECASH_PSP_URL` and `$ECASH_ESP_URL` are gone**, from `buy-psp`, `claim-psp`, `exchange`, `transfer`, `redeem` (all forms) and `handoff export-psp`, and from the settings and `--help`. The PSP and the ESP no longer have an address the wallet dials, and nor does an FSP mint (its `air.fsp` entry is an AIR address). A wallet file written before this change still reads: the library keeps the old URLs only as record keys (`live_keysets`, `swap_schedule`, a pending rollover's `url`, a handoff's `mint`), under the two constants the command line used as defaults (`http://127.0.0.1:3000` for the PSP and `http://127.0.0.1:3100` for the ESP). Records a wallet saved under a custom `--psp-url` or `--esp-url` do not match those constants, so cached live key sets and swap schedules kept under such a URL are not used.
- **Behaviour change: `buy-psp --sync` replaces `buy-psp --psp-url`.** `--sync` reads the PSP's live key sets and largest note size over AIR before building the payload; without it the payload names the key set the wallet last saw, and only the power of two is checked, as `buy-psp` without `--psp-url` did.
- **Behaviour change: the `air` cargo feature is gone and `sp-wire`'s `air-client` is always built.** The library always needs `air_server`, so building it takes the local `air_server` patch for now (README, "Setup"); an HTTP-only build no longer exists. **The `http` feature is gone too**, with `src/http.rs` (about 410 lines, of which the FSP calls and the HTTP tests were the most) and the `reqwest` dependency: the wallet makes no HTTP call. `reqwest` stays as a dev-dependency of `tests/redeem_flow.rs` alone, which calls the in-process ESP mint's operator routes. The `fsp_*` functions and `FspSync` moved to `mint_info`; `http::check_network`, `check_wire`, `verify_mint` and `fetch_window` are replaced by the AIR mint-info check (`verify_fsp`, `fsp_window`).
- **New: `NotBuilt` is gone from `WalletError`**, with the build without AIR it described. A library caller that matched it should match `WalletError::Invalid` (the missing-settings error) instead.
- **Library: the PSP and ESP calls in `mint_info` take the run's `AirSettings` instead of a base URL.** `verify_psp` and `verify_esp(wallet, air, network)`, `psp_keys`, `psp_keysets`, `psp_window` and `sync_psp_limits(wallet, air)`, `psp_claim_keys(wallet, air, text)`, `psp_post(wallet, air, route, body)`, `sync_esp_keysets(wallet, air, base)`, `sync_esp_limits`, `fetch_redeem_fees` and `esp_window(wallet, air)`, `esp_post`, `send_exchange`, `send_transfer` and `send_redeem`, `rotation_sync(wallet, air, kind, base)`, `complete_import`, `check_handoff` and `reclaim_handoff` (the last two with `(wallet, air, id)`). `base` is a record key only. Removed from `http`: `fetch_psp_keys`, `fetch_psp_keysets`, `psp_claim_keys`, `sync_psp_limits`, `sync_esp_keysets`, `sync_esp_limits`, `fetch_redeem_fees`, `send_exchange`, `send_transfer`, `send_redeem`, `post_bytes`, `send_rollover`, `rotation_sync`, `complete_import`, `check_handoff` and `reclaim_handoff` (with their `_with` forms, which moved to `mint_info` as private functions), and `mint_info`'s `over_http`, `http_keys`, `http_keysets`, `http_window`, `http_claim_keys` and `http_post` with every `!air.is_configured()` branch. The FSP functions take `(wallet, air, service, ...)`: `verify_fsp`, `fsp_keys`, `fsp_rotation`, `fsp_window`, `fsp_fees`, `send_fsp_issue`, `send_fsp_spend`, `settle_fsp(wallet, air, id)` and `fsp_sync(wallet, air, service)`; they replace `http::fetch_fsp_keys`, `fetch_fsp_rotation`, `fetch_fsp_fees`, `send_fsp_issue`, `send_fsp_spend`, `settle_fsp` and `fsp_sync` (which took a base URL).
- **`config`, `--help` and the README describe AIR as required** for the PSP and the ESP. The startup rotation check prints a note, instead of failing, when the AIR settings are missing.
- **Tests move onto AIR; four tests that only checked the HTTP branch are deleted, with their coverage kept.** `tests/air_flow.rs`, `esp_air_flow.rs`, `redeem_flow.rs`, `rotation_flow.rs`, `fsp_flow.rs` and `handoff_flow.rs` run the calls against an in-process `air_server` (one per test binary, tests taking turns, since the AIR client always dials port 5702) and the real AIR listeners of psp-mint and esp-mint, with a shared `tests/common/mod.rs`. `fsp_flow.rs` and `handoff_flow.rs` build fsp-mint's `AirIssuer` against esp-mint's real listener (they built `HttpIssuer` against an HTTP esp-mint router) and now reach fsp-mint over AIR as well, on its own real listener on the same `air_server` (`tests/common`: `FspAt`), where they ran it behind an HTTP router; each test takes its own service key, because a service's mailboxes on the shared server are its DID's. All six need listeners and an `AirIssuer` that no mint tag has yet, so they are gated by `air-listener-tests` (`--all-features` has it); `sh ~/sandbox-mint/scripts/test-wallet-against-local-mints.sh` runs them against the local mints. Deleted, each covered by an AIR test: `air_flow` `with_air_off_the_psp_is_checked_over_http`, `with_air_off_keys_keysets_and_rotation_go_over_http…` and `with_air_off_rollover_and_check_state_go_over_http…`, and `esp_air_flow` `with_air_off_every_esp_call_goes_over_http…`; the new `without_air_server_and_host_no_call_to_the_psp_is_made…` and `…_no_call_to_the_esp_is_made…` cover the missing-settings error for the two mints. The HTTP side of each "AIR equals HTTP" comparison is dropped from those two files, and the AIR side is kept.
- **New tests in `fsp_flow.rs`:** an FSP mint that cannot answer a spend now (a signed "cannot answer now", in place of the HTTP fault proxy) leaves the rollover pending and the next connection finishes it; a refused spend (memo over the mint's limit) cancels the request and frees the notes; an ESP mint that does not answer fsp-mint leaves the issue pending and the retry finishes it with the ESP transferred once; a service with no `air.fsp` entry is refused naming the setting, in the library and on the command line, which has no `--fsp-url` and names `air.fsp` in `--help`. Config tests cover `air.fsp` (file, environment, sources, duplicates, bad parts) and the old-file reads. Deleted with no AIR equal: the assertion in `handoff_flow` that a receiver is warned when its FSP mint's URL differs from the sender's (the URL is gone), and `http.rs`'s own wire tests, which tested the HTTP `verify_mint` (the AIR `verify_mint` tests in `air_flow.rs` cover the network and wire-version checks).
- Docs: README (settings table, the two "calls over AIR" sections, command table, the test section), DESIGN, REGTEST (the AIR server step, the AIR settings for the mints and the wallet, and the `curl` steps for routes that are AIR-only replaced by a note) and the help texts.

## 0.6.0 (unreleased)

- **Behaviour change: `storage.wallet` is the wallet-backup list only, and the `fsp` commands need `--service`.** `storage.wallet` is the AIR services that back up the wallet state: index 0 is the preferred service for the copy the wallet should always keep on the AIR, the rest are further backups in order, the local file stays the primary ledger, and two services are plenty (the limit stays 8). It is no longer the service FSP fees are paid to: `Settings::storage_service()` is removed, so `fsp issue`, `fsp pay` and `fsp sync` no longer default `--service` to the primary of `storage.wallet`; without `--service` they refuse with a message. `balance` and `config` no longer print a storage service. A wallet whose scripts relied on the default must pass `--service DID`. Top-up will get its own setting later (planned, not built). `storage.app` and `sp_wire::storage` are unchanged. Tests: the `storage_service` asserts are gone from the config tests, and two new tests in `src/main.rs` check that an `fsp` command without `--service` is refused and that a given one is taken.

**AIR 3.0.0 (unreleased).** Comments and docs follow sp-wire's move to air 3.0.0 (`ff41c09`) and air_server 1.0.0 (`ec6ac1f`); no code changes; the README's setup text names the new pin. The local AIR checkouts for a build are now on the branch `air3-export-secretkey` (3.0.0 plus the `SecretKey` export), and air_server is at 1.0.0.

**Wire version 3: the service ID is the 33-byte AIR DID.** Builds on `sp-wire` 0.5.0 (`WIRE_VERSION` 3). `Cargo.toml` still names `sp-wire` and the three mints (dev-dependencies) by their old tags, which move when the new releases are tagged; until then the integration tests run against local copies (`scripts/test-wallet-against-local-mints.sh` in sandbox-mint). No migration and no dual format.

- **A service is `sp_wire::ServiceDid` everywhere:** `--service` takes the 66-character DID (the old 64-character form is refused with a message that says to use the DID); the stored terms, the pending exchange, transfer and redemption, the hand-over, the FSP mint map and the balance's per-service totals hold the DID (the map keys are its 66 hex characters). `Settings::storage_service()` returns a `ServiceDid`.
- **`--service-key` is still the service's secret key, and its DID is derived from it** (the compressed public key, parity byte included), so it is the DID `fsp-mint service-key` prints.
- **Sizes:** a redemption is `120 + 187 per input + memo + 82 per output` (was `119 / 186 / 81`), and the wallet's check of `GET /fees` compares with the new constants.
- **Handoff format 2.** An FSP handoff names its service by 33 bytes, so the format version is 2 for both kinds: the strings start `SPHP2:` and `SPHF2:`. A version 1 string (`SPHP1:`, `SPHF1:`) is refused with the existing "this handoff is version 1, and this wallet reads version 2 only" message. The PSP handoff's bytes did not change, but it shares the version with the FSP one, so both moved together.
- **A wallet file from 0.5.0 that holds a service does not load** (stored terms, pending requests and the FSP mint map name the service by 64 hex characters). There is nothing to migrate: the family has no live notes.
- Tests: fixtures use the DID `02` + the generator's x coordinate; the config test checks that the parity byte is part of the ID (`03` is not `02`); the handoff tests check the version 1 and 3 refusals; the redemption tests use the new sizes (the memo that makes a one-note request exactly 512 bytes is 205 bytes, was 207).
- REGTEST.md: the service is the 66-character DID. Its recorded outputs are from wire version 2 and are not re-run; a note at the start says what moves.

## 0.6.0, the ESP's calls over AIR (unreleased)

- **The ESP's mint info, keysets, rotation window, fees, rollover, exchange, transfer and redeem go over AIR when the wallet is configured for it, and over HTTP otherwise.** The same switch as the PSP's (`air.server` and `air.host`), to the ESP's own DID. Not moved: `GET /audit` (the operator's), and there is no `GET /keys` on the ESP. `mint_info` gains `verify_esp`, `sync_esp_keysets`, `sync_esp_limits`, `fetch_redeem_fees`, `esp_window`, `esp_post`, `send_exchange`, `send_transfer` and `send_redeem`; `rotation_sync` handles either mint. The command line uses them in `exchange`, `transfer`, `redeem`, `receive`'s rollover, `sync`/`issue`/`pay` and the startup rotation check (wherever it read or posted to the ESP). The HTTP functions are unchanged and are the `http_*` branches.
- **New: `config::Party` and the ESP's DID.** `Party::{Psp, Esp}` says which mint a call is for (it moved out of `air.rs` so a build without `air` has it). New setting `air.esp_did` / `$ECASH_AIR_ESP_DID` and constant `BUILTIN_ESP_DID`, a PLACEHOLDER like `BUILTIN_SPI_DID` (a point with no known key, different from it) until the first SPI deploy. `AirSettings::placeholder_warnings` lists a warning for each placeholder in use; they are printed at every start and in `config`. `air.esp_did` without server and host is an error.
- **A refusal over AIR is the same wallet error as the HTTP `400`**, read by the same code (new `esp_replies` module, outside the `http` feature). A reply that carries `"http_status": N` with N other than 400 (the `409 in_progress`, the `413` of an exchange or transfer, the `404` of a mint that does not rotate) is a plain `WalletError::Mint` and never a refusal, so a pending exchange is not cancelled and its notes are not freed while the ESP may still be answering. A `5xx` is a signed "cannot answer now".
- **Requests are not applied twice.** The exchange, transfer and redeem requests are kept in the wallet file by the SHA-256 of the body and resent as the same bytes; the ESP answers a body it has answered from its store. The ESP and the PSP are two mints with two DIDs and may share one AIR server; their kept requests never meet.
- **The redemption ceiling the wallet assumes before it has read `GET /fees` is 15 MiB (was 64 MiB)**, to match esp-mint's new default, which is AIR's 16 MiB message cap less room for the envelope. The wallet already splits a redemption into requests under the ceiling the mint reports, so a mint that keeps the old 64 MiB ceiling is still split at 64 MiB and its larger requests can go over HTTP only (the AIR record would be over the cap).
- `--help` and `config` say which calls are asked over AIR. `PendingAirRequest` is unchanged. New feature-gated test `tests/esp_air_flow.rs` (`air-listener-tests`): all the above against esp-mint's real listener, compared with HTTP.
- Needs sp-wire's `KIND_FEES`, `KIND_EXCHANGE`, `KIND_TRANSFER` and `KIND_REDEEM` (no `WIRE_VERSION` bump) and an esp-mint with `air_listener`; no tag has them yet, so the dev-dependencies are the local copies of the local-mints script.

## 0.6.0, AIR rollover, check-state and the built-in SPI DID (unreleased)

- **The PSP's `POST /rollover` and `POST /check-state` go over AIR when the wallet is configured for it, and over HTTP otherwise.** The rollover is the swap (the rotation sync, a handoff swap on import, a reclaim); check-state is `handoff check` and the check inside `handoff reclaim`. `mint_info::psp_post` is the one place that decides, and `rotation_sync`, `reclaim_handoff` and the new `check_handoff` and `complete_import` of `mint_info` pass it to the `_with` forms of the `http` functions (`http::Post`, a function that takes the wallet, the URL, the route and the request JSON); the HTTP forms and their signatures are unchanged. `/melt`, `/burns`, `/audit` and everything to the ESP and FSPs stay HTTP.
- **A refusal over AIR is the same wallet error as the HTTP `400`** (`error::mint_refusal`, moved out of `http.rs` so the `air` feature does not need `http`): `Refused`, or `SpentElsewhere` with the positions; a body over the ceiling is a plain `Mint` error, as the `413` is. So `send_rollover` cancels, marks spent and retries exactly as before.
- **A rollover resent over AIR is not applied twice** (the mint answers a body it has answered from its store). The wallet file's `air_requests` records carry `body_hash` (the SHA-256 of the request body, hex; empty for reads and in an older file), and a kept request is found by (PSP, kind, body hash), so the same rollover resumes its request and another call never takes its place. A kept request that is never repeated is dropped after 30 days, when the next one is saved.
- **"AIR is configured" now means `air.server` and `air.host` are both set.** The SPI's DID is built in (`config::BUILTIN_SPI_DID`) and `air.psp_did` overrides it. One of server and host without the other is an error, and so is `air.psp_did` without both (it would be ignored). **The built-in DID is a PLACEHOLDER** (a point with no known key, derived in the open; documented on the constant) until the first SPI deploy, and it never passes silently: `AirSettings::placeholder_warning` is printed at every start and by `config`, `config` says which DID is in use, and the errors of an unreachable PSP name it. A test checks the point is valid and the derivation holds. `ECASH_AIR_PSP_DID` setups with server and host keep working.
- `--help` and `config` say that rollover and check-state are asked over AIR too. - **The handoff is split into two kinds. This changes the string format and the command line** (`src/handoff.rs`, `src/main.rs`). The 0.4.0 combined handoff let you build combinations that are not valid, which was a bug. Now: a **PSP handoff** (`SPHP1:`; a developer to a user): PSP notes only, never a DID key or FSP, always sealed to the recipient's DID public key with `sp_wire::seal` (AIR's own encryption; no new crypto), always swapped at the PSP mint on import with no way to opt out, and if the mint cannot be reached the notes stay unswapped (they count in the balance and can be spent: see "No lock on unswapped received PSP" below) and the swap is sent again on the next sync. An **FSP handoff** (`SPHF1:`; moving the user's own DID to a new device): always the DID secret key plus a little FSP, never swapped, not encrypted (it carries the key it would be encrypted to); the bearer and key-exposure warning is printed on export and on import. Each kind has its own types (`PspPayload` has no field for a key or FSP, `FspPayload` has a non-optional key), its own prefix and its own import; the old `SPH1:` is refused with a message. API: `export_psp_handoff`, `export_fsp_handoff`, `import_psp_handoff`, `import_fsp_handoff`, `import_handoff` (either kind), `select_psp_handoff`, `select_fsp_handoff`, `kind_of`, `HandoffKind`. Removed: `export_handoff`, `select_handoff`, `HandoffSelection`, `Payload`, `build_fsp_swap_of`, the `--swap` option, `PREFIX` and `BEARER_WARNING` (now `PSP_PREFIX`, `FSP_PREFIX`, `PSP_WARNING`, `FSP_WARNING`). Command line: `handoff export-psp --to DID --psp N`, `handoff export-fsp --fsp SERVICE:UNITS --did-key-file FILE`, `handoff import STRING [--did-key-file FILE] [--did-key-out FILE]`; `handoff export` explains the split. `Balance::unswapped_psp` and a `balance` line show PSP waiting for its swap. Old records in `handoffs_out` and `handoffs_in` read as kind `combined`. A PSP handoff is about 188 + 150 per note in characters (27 fit a QR code at level L, 21 at M), an FSP handoff about 165 + 150. The `merge FILE` after an FSP handoff and the AIR fetch is documented as a separate step; the fetch does not exist yet.
- **`send-psp` is removed; the PSP handoff gets its reclaim** (`src/handoff.rs`, `src/http.rs`, `src/legacy.rs`, `src/main.rs`; replaces the earlier decision to keep `send-psp`). Removed: the commands `send-psp`, `receive-psp` and `sent` (they print what replaces them), the `psp1` token (`Token`, `TokenNote`, `TOKEN_PREFIX`), `export_psp`, `export_psp_amount`, `begin_receive`, `settle_sent`, `sent_tokens`, `http::receive_psp`, `http::check_sent`, `http::reclaim_sent`, `Received`, and the module `send` (the swap builder moved into `handoff.rs`). Added: **`handoff check ID`** and **`handoff reclaim ID`** (`http::check_handoff`, `http::reclaim_handoff`, `Wallet::settle_handoff`, `Wallet::begin_reclaim`, `Wallet::handoff_standing`, `handoff::Standing`, `http::Reclaim`): the logic of `sent --check` and `sent --reclaim`, with the mint's `/check-state` record deciding who wins (none spent: still the sender's; all: the receiver has it and the handoff is done; some: those are dropped and the rest reclaimable) and a reclaim being a stored swap back to the sender that the mint takes or refuses against the receiver's. `OutgoingHandoff` gains `mint`, `reclaim` and `spent_elsewhere` (all with defaults, so old files read), and `HandoffState` gains `Reclaimed`. A reclaim's outcome and the handoff's state change in the same write. `cancel` is refused while a reclaim is stored.
- **Old `send-psp` records are migrated, not kept** (`src/legacy.rs`, `WalletData::migrate_legacy`). A wallet file's `sent` list is read as before and each token becomes a PSP handoff record with the token's id when the file is opened and when two copies are merged (pending, a stored reclaim, received, conflict, reclaimed; the table is in `legacy.rs`). They are checked and reclaimed with `handoff check` and `handoff reclaim`, including a reclaim that was stored and not sent. The file is rewritten without `sent` at the next save. A swap that `receive-psp` stored and did not send (`receive|<id>`) is still sent at the next start; `Wallet::legacy_receive_psp` and a `balance` line show it, and it is not counted in the balance (the wallet holds no secrets for those notes). A `psp1` token string can no longer be imported.
- **No lock on unswapped received PSP.** A PSP handoff's notes are added to the wallet on import and **count in the balance**, with a stored swap beside them. The swap is sent first whenever the mint can be reached: on import, then on every sync (`rotation_sync` sends stored swaps first) and at every start. Spending a note at the mint burns it just as the swap does, so the lock added nothing once `send-psp` was gone. A stored swap is made to fit what the wallet still holds before it is sent (`Wallet::live_swap`), the ordinary rollover leaves those notes alone, and a note the mint says is spent (the sender reclaimed first, or a copy was received first) is moved to the spent record, so it leaves the balance, and the rest is swapped (`Wallet::swap_found_spent`). Any other refusal drops the stored swap and leaves the notes in the balance. `Balance::unswapped_psp` is now a part of `Balance::psp` (it was in no total), and the `balance` and `handoff list` lines say so. **Behaviour change:** a received PSP handoff can be spent before it is swapped; until the swap goes through the sender can still reclaim it.
- Tests: `tests/handoff_flow.rs` replaces `tests/send_flow.rs` (removed): reclaim before the receiver swaps (fresh notes for the sender, a late receiver loses them from the balance), reclaim after the receiver swapped (nothing comes back, done), a note spent elsewhere (check says partly, the rest is reclaimed; a receiver drops the spent one and swaps the rest), unswapped notes counted and spendable and swapped at the next sync, a spent note left out of the swap, and old `send-psp` records loading (pending, received, reclaimed, and a stored reclaim finished by `handoff check`). ## 0.3.0 (2026-10-16)

- **ESP notes are powers of two.** The ESP mint now refuses any ESP amount that is not a power of two (`bad_denomination`), so the wallet only builds those. New `src/split.rs`: `split` (a total into the fewest powers of two, largest first), `split_into` (the same total in exactly n notes, by halving the largest) and `check_denomination`. `build_exchange` splits the amount and the change; `build_transfer` splits the total; an explicit `--amounts` list is refused if any size is not a power of two, and a chosen input note that is not one is refused. A redemption's decline and refund outputs are split the same way: the count of outputs and the fee depend on each other, so `allocate` tries counts upward for the smallest that fits (see the ESP DESIGN.md). `redeem::MAX_OUTPUTS_PER_TERMS` (64, one per size) is public and is the worst case the group-size estimate uses.
- Tests: `split` and `split_into` (round-trip, largest first, above 2^63, the limit); an amount that is not a power of two is refused in the exchange and the transfer; a total above one note splits over several notes, and so does the change; the redemption fee and count tests and the end-to-end flows moved to power-of-two sizes. **Needs esp-mint with the same change:** the integration tests use the mints at their git tags, so they see the new check only after the tag moves.
- Tests can be run against the local mint folders with `sandbox-mint/scripts/test-wallet-against-local-mints.sh` (see the README), for a release where the wallet and a mint change together. The script runs every test file to the end (`--no-fail-fast`) and also runs fsp-mint's tests.
- Tests: the wallet's three mint-hosting tests (`redeem_flow`, `fsp_flow`, `rotation_flow`) set esp-mint's new `in_flight` field, so they build against esp-mint after the lock change, not the `v0.2.0` tag. `rotation_flow` uses ESP notes of 4, 4 and 2 (powers of two); `flow` counts every note it holds.
- Docs: why there is no ESP split command (holders convert ESP to FSP straight away), and why a lost wallet file is not rebuilt (the AIR keeps the storage redundant).
- **A swap time is never the second the set starts.** The random delay is now 1 to the window (0.5% of the period, at most 72 h), not 0 to the window. With 0 possible, a wallet that synced the second a set started swapped at once, for about 1 wallet in 19 on a 1-hour period (1 in 4,321 on the 240-hour test period). It showed as a rare failure in `rotation_flow`: the rotation tests set the mint's clock to the start and expect "will be rolled over" before the swap, and the first sync had already done it. A unit test checks 20,000 draws.
